# Native iPhone App (Lock Screen, Health, Band) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Functional Trainer as a native iPhone app: a Live Activity on the lock screen showing the active workout timer, the whole current block and a Next button, plus Apple Health saving, Xiaomi Band 11 heart rate and per-block wrist notifications.

**Architecture:** Capacitor 8 wraps the existing Vite and React build unchanged. A Swift plugin (`TrainerNative`) owns ActivityKit, notifications, HealthKit and Bluetooth. The web code talks to it through one TypeScript bridge that is a no-op on the web. The Xcode project is generated by XcodeGen from `ios/project.yml`, the same approach as Hushloom, with an app target and a widget extension for the Live Activity.

**Tech Stack:** Capacitor 8.5.2 (`@capacitor/core`, `cli`, `ios`), `@capacitor/filesystem` 8.1.3, `@capacitor/share` 8.0.2, Swift 6, iOS 18 target, ActivityKit, WidgetKit, AppIntents, UserNotifications, HealthKit, CoreBluetooth, XcodeGen, Xcode 27.1, Vitest 2.1.9, XCTest.

**Spec:** `docs/superpowers/specs/2026-10-20-native-ios-lock-screen-design.md`

## Spec deviation (decided here; Steven should know)

The spec says JS is the source of truth and Swift keeps no copy of the screen list. That can't deliver the lock-screen **Next**. When the phone is locked, iOS suspends the web view, so a `LiveActivityIntent` that relays to JS does nothing until the app is opened.

**Ruling:** at workout start, JS sends Swift the full list of rendered screen snapshots (display text only, no plan logic). Swift owns the current index while the app is backgrounded. Lock-screen Next advances it, then updates the Live Activity and the wrist notification itself. When the app comes back, JS reads Swift's index and jumps to it.

This is still "one source of truth at a time": whichever side is awake owns the index, and every change is mirrored to the other side. If the app has been killed, Next opens it, and the screen resumes from `wp_state_v3`, the existing behavior.
